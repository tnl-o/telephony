# Локальный стенд (Docker)

Актуальная инструкция: [Доставка внутренних звонков](../docs/internal-calls.md).

1. Скопируйте `.env.example` в `.env` и укажите `PUBLIC_HOST` — LAN-IP или DNS-имя сервера.
2. Из `dev/` выполните `docker compose up -d --build`.
3. Откройте `https://<PUBLIC_HOST>:8443`. Доверьтесь общему сертификату из `dev/ssl/cert.pem` на клиентских компьютерах.
4. Войдите как `alice` / `alice123` и `bob` / `bob123` в двух браузерах.
5. Дождитесь «На линии» у обоих абонентов и проверьте вызовы в обе стороны.

SIP WSS идёт напрямую на TCP **7443** с сертификатом сайта. Порт должен быть
доступен клиентам. Параметр `SIP_WSS_URL` нужен только для явного переопределения адреса.
Для передачи звука также откройте UDP 16384–16448 и проверьте публичный RTP-адрес АТС.

Каталог пользователей АТС формируется backend из `dev/data/users.json` в общем
Docker volume. Статический XML с номерами 1000–1039 не используется; ручная
генерация каталога и согласование паролей с ним не нужны. SIP-домен dev по
умолчанию `100.64.0.10`, одинаковый у backend и FreeSWITCH.

Если сертификат создан до этих исправлений или изменился PUBLIC_HOST, замените
его парой с правильным SAN и перезапустите nginx и freeswitch; пример в основной инструкции.

Это стенд для разработки с тестовыми логинами; конфигурация доступа для эксплуатации
требует отдельной настройки.
