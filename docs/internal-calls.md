# Доставка внутренних звонков

## Что исправлено

Внутренний dialplan получает адрес получателя через
`${sofia_contact(internal/${destination_number}@$${domain_name})}`.
Это зарегистрированный контакт с транспортом и маршрутом `fs_path`, а не
попытка вызвать `номер@IP-АТС` как удалённый SIP-адрес.

Браузер подключается прямо к `wss://<hostname сайта>:7443`. FreeSWITCH берёт
сертификат и ключ из того же каталога, что nginx. Отдельного сертификата WSS
из Docker image больше нет. SIP-домен задаётся одинаково для backend и АТС
через `SIP_DOMAIN` в compose; по умолчанию он различается для dev и основного стенда.

Backend публикует полный XML каталога атомарно, последовательно обрабатывает
параллельные публикации и ожидает подтверждение `reloadxml` после входа и
изменения номера. Неуспешная синхронизация больше не выдаётся за успешный вход.
Повторный вход повторяет синхронизацию, в том числе после временного отказа АТС.

Клиент сохраняет текущий вызов при втором входящем, отклоняя его с `486 Busy Here`.
События старой сессии не очищают новую, а `accepted` и `confirmed` не запускают
два таймера. Старые данные из localStorage не подменяют SIP-реквизиты нового входа.

## Основной стенд

1. В `.env` укажите `LAN_PUBLISH_IP=<адрес сервера в LAN>`.
2. Сгенерируйте сертификат для того же адреса из корня репозитория:

   ```sh
   ./scripts/generate-ssl.sh <LAN-IP>
   docker compose up -d --build
   ```

3. Добавьте `config/ssl/ca.pem` в доверенные сертификаты клиентских компьютеров.
   Открывайте сайт по адресу, указанному в SAN сертификата. Для собственного DNS-имени
   установите соответствующий доверенный сертификат в `config/ssl/cert.pem` и ключ в `key.pem`.
4. Разрешите доступ клиентов к TCP 443 и **TCP 7443**. Для звука нужен также
   опубликованный UDP-диапазон RTP; успешный вызов и успешная передача звука проверяются отдельно.
5. После обновления выйдите из приложения и войдите снова в обеих вкладках,
   чтобы обновить ранее сохранённые WSS-адрес и SIP-реквизиты.

При обновлении уже существующей установки используйте существующий том каталога:
удалять пользователей или Docker volumes не требуется. Backend перезапишет свой `users.xml`.
После смены добавочного абонент должен войти заново для регистрации нового номера.

## Dev-стенд

В `dev/.env` скопируйте значения из `dev/.env.example` и задайте `PUBLIC_HOST`
равным LAN-IP или DNS-имени сервера. Первый запуск nginx создаёт сертификат с этим
адресом в SAN; FreeSWITCH ожидает его появления и использует тот же сертификат.

```sh
cd dev
docker compose up -d --build
```

Откройте `https://<PUBLIC_HOST>:8443`, добавьте `dev/ssl/cert.pem` в доверенные
сертификаты клиентов. Откройте TCP 8443 и 7443. Вход: `alice` / `alice123` и
`bob` / `bob123` в разных профилях браузера или на разных компьютерах.

Если `dev/ssl/cert.pem` создан старой версией или PUBLIC_HOST изменён, nginx
не заменяет его автоматически. Создайте новую пару с правильным SAN и замените
`dev/ssl/cert.pem` и `key.pem`, затем перезапустите nginx и freeswitch. Пример
для IP (OpenSSL на хосте, выполнять из корня репозитория):

```sh
openssl req -x509 -nodes -days 825 -newkey rsa:2048 \
  -keyout dev/ssl/key.pem -out dev/ssl/cert.pem \
  -subj "/CN=telephony-dev" \
  -addext "subjectAltName=DNS:localhost,IP:127.0.0.1,IP:192.168.0.11"
```

Замените последний IP на ваш. Для DNS-имени используйте `DNS:phone.company.local`.
Повторно установите обновлённый сертификат в доверенные на клиентских компьютерах.

## Проверка двух абонентов

1. В обоих браузерах дождитесь статуса **«На линии»** в заголовке. Значок контакта
   «онлайн» отражает присутствие в приложении и не заменяет SIP-регистрацию.
2. На сервере проверьте регистрации (в dev имя сервиса то же):

   ```sh
   docker compose exec freeswitch fs_cli -x "show registrations"
   docker compose exec freeswitch fs_cli -x "sofia_contact internal/1001@100.64.1.10"
   ```

   Подставьте фактический номер получателя; в dev домен по умолчанию `100.64.0.10`.
   Команда должна вернуть контакт, а не `error/user_not_registered`.
3. Позвоните от A к B: у B должен появиться баннер входящего с кнопкой «Ответить».
   Ответьте, завершите разговор и повторите вызов в обратную сторону.
4. Проверьте повторный вызов после обновления страницы и переподключения SIP,
   отклонение занятого абонента и смену номера с последующим новым входом.
5. Если баннер отсутствует, на один вызов включите
   `fs_cli -x "sofia profile internal siptrace on"`, сохраните логи FreeSWITCH и
   сообщения `[SIP]` обоих браузеров, затем выключите `siptrace off`.

## Автоматическая проверка и границы результата

```sh
npm ci
npm --prefix backend ci --ignore-scripts
npm test
npm --prefix frontend ci
npm --prefix frontend run build
```

Тесты включают реальный HTTP backend с тестовым TCP ESL-сервером, проверки
протокольных ошибок/таймаутов, генерации XML, гонки публикаций и событий SIP-клиента.
Они не заменяют реальную АТС: тестовый ESL не выполняет FreeSWITCH dialplan и
не доставляет SIP INVITE. Docker/FreeSWITCH и два реальных браузера в среде
разработки исправления не запускались; фактическая доставка требует проверки выше.

Известные замечания аудита по аутентификации по ФИО и отсутствию прав на admin API
относятся к отдельной работе; это исправление доставки их не устраняет.
